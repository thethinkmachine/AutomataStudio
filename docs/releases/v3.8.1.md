## What's Changed

### Fixed
* **Large Turing machines no longer freeze the app.** Checking the behaviour of a machine with a couple of hundred states, or opening the Library's Submit page with one on the canvas, could stop the app for hours. One of the halting provers, finite automata reduction, had a limit that only meant something for busy-beaver-sized machines. It now stops after a bounded amount of work on a machine of any size, and says that it reached its limit. A 198-state machine that used to hang is answered in about three seconds.
* **A wrong "never halts" on machines with more than 32 states.** The n-gram CPS prover could mix up two states of a large machine and report a proof that the machine never halts when it had proved nothing; some machines it said this of do halt. Machines with 32 states or fewer were never affected, so every busy beaver result stands. If you were shown "never halts, by n-gram CPS" for a larger machine, check it again.

### New
* **Babel has its own tab,** beside the Library (<kbd>3</kbd>). It used to be a section inside the Library. Algorithms, Grammar and Reference move along to <kbd>4</kbd>, <kbd>5</kbd> and <kbd>6</kbd>.
* **Find a machine from words.** Type the words a machine should accept and reject, such as `accepts:{ab, abab} rejects:{a, b}`, into Babel's search or the Library's, and get the smallest DFA that agrees with every one of them. Put `type:NFA` in front for the smallest NFA instead. Its page lists the shortest words it accepts, so you can see what your words left open and add one to settle it.
* **Search filters take sets.** `accepts:{0110, 11}` is every word in the set at once, and any filter takes one: `type:{DFA, NFA}`. The empty word can be written `ε`, `eps`, `λ` or `""`.

### Command line
* **`automata halts` comes back from a large machine.** It used to run without end on one. `--far-ops N` sets how much work finite automata reduction may do on a machine, and `--far-ops inf` removes the limit.
