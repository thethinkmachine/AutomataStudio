## What's Changed

### New
* **The Minsky register machine.** A new machine type in the Turing Machines group: registers that each hold a whole number, and moves that add one (`x+`), take one away when there is one (`x−`), test for zero (`x = 0`), or jump (`ε`). It reads no word. Its input is the starting values of the registers you mark as inputs, and its answer is the registers you mark as outputs once it halts. Two registers are already enough to do anything a Turing machine can, and the Reference page shows why.
  * **Registers** take the alphabet's place in the Workspace panel. Name them, mark each one in, out or both, and rename one in place: the edges that use it follow.
  * **Running it:** type `3, 4` to fill the input registers in order, or `y=4, x=3` to name them. Registers are drawn as rows of pebbles, and as numbers once they grow past a size you can set in Settings.
  * **Testing it:** a batch line can expect a verdict, an output, or both (`3, 4 => 12`). The Language panel tabulates small inputs, as a grid for two of them.
  * **Building blocks** work, with `ε` as the exit move, so the subroutines register machines are programmed with (clear a register, copy one, add one to another) are blocks. The multiplication example is built from one.
  * Three examples (add, multiply, and an even-or-odd test), a guided tour, a build lesson, the machine wizard and StateMate all know the new type.
* **Generate code from a Minsky machine.** Export it as JavaScript, Python, Java or C, in any of the three shapes, and get a `run(inputs)` that returns the verdict and the output registers. It also exports as an XState or SCXML statechart, and as Jest or pytest suites built from the machine's own results. A run that never halts stops at the step limit and answers "unknown".
* **Exercises with a Minsky machine as the answer.** Create Exercise works from a register machine. A student's machine is checked on every input up to a bound you choose: it must give the same verdict, and the same outputs wherever it accepts. The student's copy keeps your input and output registers, not your working ones.
* **Machine codes for Minsky machines.** Copy Machine Code writes one as a single line, such as `minsky.ib:(0-B0=Z)_1+A` for adding x to y. Paste it onto any canvas, or share it as a machine link. Register names are not part of the code, so a pasted machine names its registers r1, r2, ….
* **The machine file format is documented** for anyone writing `.automaton` files by hand or with a script, and the website serves it at `/llms.txt` so AI assistants can read it.

### Improved
* **States are redrawn, and every mark means one thing.** The ring around a state used to mean several things at once. Green meant the start state, but also "edges leave here" when you highlighted a state's outgoing edges, and two meanings at once drew mismatched rings. Now:
  * **What a state is** has its own mark. The start state has its arrow, an accepting state has a gold inner ring, a Moore state shows its output under a short line, and a parity priority sits in a badge on the rim (filled when the priority is even).
  * **What is happening to it** (hovered, selected, on the run's current step, rejected, highlighted) changes only the outer ring and the fill. So a selected accepting state still reads as accepting.
  * **Selection is purple**, as it is for edges and notes.
* **State names read like a textbook.** `q0` is drawn as q₀ and `q_even` as q with "even" below. Long names shrink to fit inside their circle instead of running over it. The formal definition uses the same names.
* **The formal definition is shown whole.** It used to be cut off after a few lines, hiding F and δ on a PDA or a Turing machine. It now grows to fit and is set at the panel's size.
* **Cleaner side panels.** Section titles are plain words with their symbol (Alphabet Σ, States Q, Transitions δ), counts of zero are no longer shown, and both panels label things the same way.
* **The toolbar opens at the bottom left** of the canvas, out of the way of the diagram. If you have moved it, it stays where you put it.
* **Open a file from the start screen.** The empty canvas has an **Open file** button next to the examples.

### Command line
* **`automata` runs Minsky machines.** `automata run machine.automaton 3,4` prints the verdict and the output registers, and `automata test` checks lines such as `3, 4 => 7`. `automata codegen`, `automata grade` and `automata convert --to code` work on them too.

### Fixed
* **The playback speed knob is no longer cut off** in the Run tab on a narrow panel or a long run. The controls make room by dropping the speed's "1×" label first; the knob still shows the speed, and its tooltip gives the number.
* **The keyboard focus ring on the step buttons is drawn whole** instead of as two thin bars.

3.7.3 was never published, so its changes are included here.
